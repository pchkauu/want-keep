# Дизайн-контракт Want Keep

[English](design.en.md) · [Экраны](screens.md) · [Навигация](navigation.md)

D-30/D-31, REQ-077–REQ-087, AC-094–AC-104. Визуальная основа task-7.10 реализована; продуктовые экраны и их полная приёмка остаются последующим задачам. [Доказательства и границы](evidence/task-7.10-design.md).

## Платформа и характер

Только desktop web на ноутбуке macOS в реальных Chrome и Arc. Контрольные окна: 1280×720 и 1440×900 CSS px, масштаб 100% и 200%. Изменение размеров окна сохраняет доступ к действиям, числам и формам. Мобильная адаптация, нижняя навигация, установка на домашний экран и телефонные контрольные размеры исключены. Браузерный push остаётся.

Dark modern pixel fintech: технологичный, спокойный, собранный интерфейс. Свободное пространство и ясная иерархия важнее декоративного заполнения. Уточнение пользователя: сдержанный киберпанк и архитектурный ритм Ближнего Востока. Обсидиановые плоскости, точечный фиолетовый свет, бело-фиолетовое название, редкий песочный акцент и формы арок. Референсы из переписки задают материалы и настроение; телефоны и платёжные карты из иллюстраций не расширяют desktop-функции MVP. Без обводок карточек и полей, декоративных контуров, неоновых сеток и повсеместного свечения. Группировка использует пространство, типографику и заливки; геометрия остаётся в брендовых образцах, а не вокруг каждой операции. Pixel-характер не превращает формы и таблицы в ретро-игру. Светлой темы нет, включая первый кадр загрузки и системные элементы страницы, где браузер допускает оформление.

## Токены

| Роль | Целевое значение и применение |
| --- | --- |
| background | `#1A1A1A`, постоянный фон |
| surface / surface-raised | `#202020` / `#262626`, вложенная область и панель |
| brand / primary | `#5F4EF5`, основной CTA, бренд, выбранный акцент |
| text-primary / secondary | `#F5F5F5` / `#B3B3B3`, основной и вторичный текст |
| brand backdrop / architecture | `#111114` / `#18171E`, глубокие плоскости брендовой композиции, без замены основного фона |
| sand / warm surface | `#C7AF8F` / `#242220`, небольшие тёплые акценты |
| accent-readable | `#A79BFF`, мелкий акцентный текст |
| compatibility aliases | `border`, `input`, `ring` сохраняются для shadcn/Tailwind; наличие алиаса не предписывает обводку |
| focus | Инверсия: заливка `#F5F5F5`, текст `#1A1A1A`; без обводки, заметна также при hover/active |
| success / warning / error | `#83C9A0` / `#D8B36A` / `#E58B91`, текст/значок на тёмной поверхности; цвет сопровождает подпись |
| spacing | Шаг 4 px; рабочие интервалы 8/12/16/24/32/48, крупное пустое пространство по композиции |
| radius | 2 px badge, 4 px поля/обычные кнопки, 8 px панели и крупный CTA входа |
| motion | Обычные переходы 150–200 ms; отдельный контракт событий ниже |

Единый источник — CSS custom properties в `web/src/design-system/theme.css`; shadcn/Tailwind ссылаются на них. [Матрица разрешённых пар](design-contrast.md) вычисляется из CSS без округления перед сравнением с порогом. Normal CTA — `#5F4EF5`, hover — `#6B5AF6`, active — `#5142D5`, подпись — белая. Selected использует читаемый фиолетовый на `#262626` и знак выбора; disabled сохраняет читаемую подпись без доступного действия. Focus инвертирует заливку и подпись. Исключения декоративных/неактивных алиасов не применяются к тексту или значимому индикатору. Обычный текст ≥4.5:1, крупный ≥3:1; значимые границы/индикаторы ≥3:1. Брендовый `#5F4EF5` на `#1A1A1A` даёт около 3.23:1 и не подходит для мелкого текста; белый на фиолетовом около 5.39:1. Фиолетовый логотип допустим как брендовый знак, подписи и помощь используют читаемый текст. [W3C: contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

Цвета статусов — инженерные значения по умолчанию внутри согласованной приглушённой палитры. Ошибка не обозначается только красным, прогноз — только прозрачностью, выбранный участник — только фоном. Минимальные тени допустимы у всплывающих областей, постоянные карточки разделяются заливкой и пространством, без обводок.

## Типографика и логотип

- Pixelify Sans: логотип/название, крупные заголовки, ключевые суммы, отдельные badges/акцентные кнопки. Не использовать для плотных строк операций, многострочного объяснения или мелкой формы.
- Manrope: транзакции, формы, таблицы, описания, настройки и вторичная информация. Базовый UI 14–16 px с достаточным межстрочным интервалом; крупные суммы 28–40 px по доступной ширине. Критичная сумма не обрезается многоточием.
- Локальные полные variable TTF: Pixelify Sans 400–700 и Manrope 200–800, без конвертации/подмножеств. OFL, исходные URL, закреплённые ревизии и SHA-256 находятся в `web/public/fonts/manifest.json`. `font-display: swap`, синтез начертаний отключён.
- Pixelify Sans → Manrope → system-ui → sans-serif для бренда; Manrope → system-ui → sans-serif для интерфейса. В выбранном Pixelify Sans отсутствуют «О», «П», ₽, ₿ и узкий неразрывный пробел; нужные glyph берутся из fallback. Manrope покрывает перечисленные буквы и валютные знаки, узкий пробел получает системный fallback. Pixelify Sans не поддерживает `tnum`; таблицы и сопоставляемые суммы используют Manrope с табличными цифрами.
- RUB/USD/USDT/USDC/BTC/ETH представлены точными строками, включая 18 дробных знаков USDC/ETH и предел 256 символов. Суммы не проходят через `Number`, не обрезаются многоточием; перенос сохраняет все разряды. [Отчёт покрытия шрифтов](evidence/task-7.10-design.md#покрытие-шрифтов).


[Исходный логотип](assets/logo_512px.svg) предоставлен пользователем. Файл с именем 512px имеет `viewBox="0 0 455 512"`: сохранять пропорции; для квадратного контейнера добавлять отступы. Цвет `#5F4EF5`, пиксельная геометрия без сглаживающих декоративных искажений. Не перерисовывать автоматически и не заменять emoji.

## Авторизация по референсу

Источник — изображение экрана, присланное пользователем в переписке; Figma node/точные размеры не исследовались. Это визуальный референс композиции, а не измеренный макет.

Компактный знак и Want Keep по центру тёмного пространства. Ниже с заметным интервалом одна основная кнопка `Log in with Passkeys` / «Войти с passkey». Ширина блока ограничена и учитывает обе локали; экспортные пиксели напрямую не копируются. Ненавязчивые язык и «Не получается войти?» / “Trouble signing in?” не конкурируют с основным действием. Нет банковских логотипов, дашбордовых карточек и полей пароля на входе.

Системное ожидание passkey, отмена и ошибка занимают предусмотренную область статуса; знак/название/CTA не скачут. Ошибка содержит повтор и помощь; отмена не объявляется поломкой. Recovery остаётся самостоятельным SCR-002. Акцентные анимации финансовых событий на входе не запускаются.

## Компоненты и доступность

shadcn/ui на Base UI, исходники компонентов принадлежат Want Keep. Выбор Base UI фиксируется явно при настройке, версии/lockfile — в task-1.1/task-7.11; не полагаться на изменяемый CLI default. Официальный shadcn поддерживает Base UI. [Документация shadcn](https://ui.shadcn.com/docs/changelog/2026-07-base-ui-default).

`web/src/design-system/` владеет токенами, примитивами и motion. Feature владеет экраном/формой/представлением; деньги, права и бюджеты считает домен сервера. Не создавать глобальный универсальный экран или скрытый API-доступ в визуальном компоненте. Новая анимационная библиотека не обязательна: сначала CSS/SVG и существующий стек.

Каталог компонентов содержит default/hover/active/focus/selected/disabled/loading/error состояния: кнопки, money/date/text fields, select/combobox, формы, dialog/alert/sheet, navigation/tabs, таблицы/фильтры/pagination, badges/alerts/toasts, tooltip, empty/skeleton, chart legends и карточку результата AI. Стандартный стиль shadcn заменяется по токенам, типографике и композиции. Каталог — dev/test-инструмент, не экран семейного продукта.

Все интерактивные элементы доступны Tab/Shift+Tab/Enter/Space по семантике. Escape закрывает временный слой и возвращает фокус; фокус не скрывается sticky-областями. Диалог имеет название/описание, удерживает фокус, не вкладывается в другой диалог; длинная задача — страница/панель. Tooltip дополняет подпись, но не является единственным объяснением. Ошибки связаны с полями, прогресс/результат сообщается assistive technology без спама. График имеет текстовый вывод и доступную таблицу. Zoom не скрывает CTA и суммы; горизонтальная прокрутка допустима внутри обозначенной сложной таблицы, не формы/всей страницы.

## Контекстные анимации

Анимация отвечает на событие, а статичная подпись объясняет результат и остаётся доступной. Ни эффект, ни цвет не являются единственным подтверждением. Звук, мигание, стробоскоп и постоянно движущиеся декоративные фоны не нужны.

| ID | Событие и эффект | Ограничение |
| --- | --- | --- |
| MOT-01 | Счёт добавлен в учёт: короткий запуск пиксельной ракеты у подтверждения, 600–1000 ms | Только подтверждённое создание; не просмотр карточки и не открытие банковского продукта |
| MOT-02 | Подтверждённое пополнение накопления: несколько огоньков вокруг прогресса, 600–1000 ms | Principal не объявляется доходностью; прогноз и повторный импорт не запускают эффект |
| MOT-03 | Фактически достигнута цель: локальное пиксельное конфетти, 1000–1600 ms | Один раз на подтверждённое событие достижения; возврат/исправление не скрываются праздником |
| MOT-04 | Крупное совместное достижение: мягкое диско из медленно смещающихся геометрических акцентов, до 1800 ms | Вариант MOT-03 для завершённой совместной цели, без вспышек и резкой смены яркости; не накладывается на конфетти |
| MOT-05 | Лимит впервые превышен: спокойное появление warning-значка, 150–200 ms | Статичное сообщение о величине превышения и «Посмотреть план»; без праздничной награды за перерасход |

Декоративные эффекты включены по умолчанию при отсутствии `prefers-reduced-motion`; участник может отключить их в SCR-031. При reduced motion все MOT заменяются статичным знаком и текстом, независимо от настройки. Escape завершает декоративный эффект без отмены операции; эффект не перехватывает pointer/focus, не перекрывает суммы/формы, не сдвигает layout. Финансовые числа сразу показывают подтверждённое значение, без count-up через ложные суммы.

Триггер — подтверждённое типизированное событие приложения; чтение страницы, ответ AI, optimistic update и котировка не являются событием достижения. Event ID и персональное подтверждение показа предотвращают повтор в другой вкладке, при retry/reconnect или обновлении. Исторический backfill создаёт финансовые факты, но не очередь старых праздников. Из нескольких подходящих эффектов показывается один, остальные остаются статичными событиями. Дедуп показа не влияет на персональное прочтение уведомления. При неизвестном исходе не праздновать до сверки; последующая коррекция оставляет понятный новый результат. task-7.15 материализует eligibility/ack контракт, task-7.12 проверяет реальные браузеры.

## Оценка UX

Для каждого SCR: вопрос → главный ответ → действие → объяснение → детализация. Служебные поля не занимают первичный уровень; суммы подписаны как доступные/зарезервированные/ожидаемые. Ошибки называют проблему и действие, а частичная история объясняет ограниченность вывода. Принципы ясного статуса, привычного языка, контроля, предотвращения ошибок и постепенного раскрытия применяются к конкретным сценариям. [Nielsen Norman Group](https://www.nngroup.com/articles/ten-usability-heuristics/).

AC-102: оба участника без подсказок разработчика определяют дневной лимит/кассовый риск, объясняют сумму обзора, вносят чек и различают создание/связь, исправляют доли, объясняют резерв цели, справляются с reauth/ожиданием AI, входят и восстанавливают свой доступ. Протокол фиксирует ожидаемый ответ на синтетических данных, фактический ответ, ошибки, время и браузер. Автотесты Chromium не заменяют это наблюдение и реальные Chrome/Arc. Полное соответствие WCAG не заявляется без отдельного аудита.

## Воспроизводимые образцы

`/__design/tokens` доступен только в dev/test: брендовая композиция, RU/EN-типографика, точные суммы, состояния и контрастные пары. Образцы и их CSS исключены из production bundle. `make test-web FILTER=design-tokens` проверяет токены, ресурсы и матрицу; `make e2e SCENARIO=design-tokens` проверяет Chromium. Длительности MOT-01–05 заданы как 800/800/1400/1800/200 ms; reduced motion обнуляет их и обычные переходы. Финансовые триггеры и сами эффекты принадлежат task-7.15.

По уточнению пользователя ручная проверка текущей task-7.10 проводится в Chrome. Arc остаётся в общей продуктовой матрице последующей приёмки; здесь не заявляется проверенным.
