# Glossary

[Русский](glossary.md)

| Term | Meaning and boundary |
| --- | --- |
| User / Member | A separate sign-in identity / its household membership and role. |
| Household | Shared financial and access scope of members; configured membership limit. |
| Owner / Actor | Ownership of a specific resource / the user or system principal performing an action; independent dimensions. |
| Allocation | Attribution of one amount to members; not a separate monetary payment. |
| Reimbursement | An explicit inter-member debt and settlement; excluded from household wealth. |
| Connection | A platform-account connection, read method, capability and session state. Not a financial account. |
| Account | An owned account for one asset/purpose; may be cash, bank, credit or crypto. |
| Card | Access to an account; a separate card does not necessarily imply a separate balance. |
| Asset | RUB, USD, USDT or BTC. A USDT network is a transaction/address attribute, not another currency. |
| Money | An exact decimal amount plus asset. Formatting/conversion does not alter the original value. |
| SourceRecord | Immutable retrieved evidence with source, namespaced ID and revision/time; not a finished business decision. |
| Transaction | One economic event with type, state, monetary legs and evidence. |
| Posting | An account change within an atomic transaction; not every posting is an expense. |
| Opening balance | The selected period's starting point; not income. |
| BalanceSnapshot | A source-reported state at an instant; reconciled with the ledger without hiding discrepancies. |
| Pending / Posted | Awaiting confirmation / posted movement. Holds affect availability but are not actual expenses. |
| Transfer / Exchange | Movement of owned money / conversion with two currency legs. Principal is not consumer spending. |
| Fee / Funding | A fee / periodic trading payment. Sign and net-P&L inclusion come from source contracts. |
| Refund | A return with actual receipt date and linkage to the original expense/item. |
| Reconciliation | Comparison of time-aligned balances, transactions and coverage with explainable discrepancies. |
| Category / Merchant / Item | Expense type / seller / receipt line item. Independent analytical dimensions. |
| Obligation | A dated planned payment; it does not create an actual transaction by itself. |
| Flexible allocation | A monthly variable-spending category limit in one currency. |
| Expected income | A dated planned receipt; not received money until actual fulfillment. |
| Goal reservation | One-time allocation of owned money to a goal, reducing availability without an external transfer. |
| Available allowance | A limit funded by already available owned money in the corresponding currency. |
| Forecast allowance | A scenario with expected receipts/payments by date; not a promise of liquidity. |
| Coverage | Boundaries, completeness and freshness of data/valuation; partial and unknown are meaningful states. |
| AI proposal / Clarification | A proposed authorized command / request for a missing fact. Model output is not itself a posting. |
| AI review revision | Review of a specific transaction revision; stale results cannot apply to a newer version. |
| XIRR | Annualized money-weighted return from dated external flows and terminal valuation; neither contract APR nor a promise of future return. |
| RPO / RTO | Actual potential data-loss window / recovery time. Mac backup RPO depends on reachability. |
| REQ / AC / task | A testable requirement / observable criterion / task with dependencies and outcome evidence. |
| Ready | A verdict on specification/plan sufficiency. Neither successful runtime proof nor deployment authority. |
