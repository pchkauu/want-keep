# Task-3.2 — входной контракт коннекторов

Реализован внутренний ingestion-контракт версии 10. База реализации: `cedbe3ba8384071e0e958167d37899ade557c0bc`; ветка: `feat/task-3.2-ingestion-contracts`. Зависимости task-3.1, task-1.2, task-2.1 и task-2.2 включены. Production и реальные платформы не изменялись.

## Доказанный результат

`collector/contracts/v10/ingestion.openapi.yaml` — единый источник wire-моделей. `make generate-contracts` создаёт Go transport DTO в `backend/internal/integrations/contract/generated` и TypeScript-типы в `collector/src/contracts/generated`; `make check-contracts` воспроизводит оба результата во временном каталоге. Строгие Go/TypeScript codecs одинаково отклоняют отсутствующие required-поля, явный `null`, неизвестные поля и trailing JSON; также проверяются Unicode code-point и отдельные byte limits, NUL/lone surrogate, канонический base64 без CR/LF, digest, действительные даты, канонические UTC-instant с `Z`, decimal-строки, discriminators и точное эхо server-issued job/binding/admission revision/cursor для страниц и provider failures. `nextCursor` либо отсутствует, либо непустой. Cursor проверяется только при сохранении sync-result; неизменяемая lease identity продолжает обслуживать heartbeat после продвижения checkpoint. Необязательный lookback остаётся `nil`, явный ноль отклоняется; совокупный coverage после объединения с checkpoint принимает не более 100 уникальных gaps по 2000 code points, а переполнение откатывает страницу без продвижения cursor. Необязательные пустые merchant, note, network и aliases канонизируются как отсутствие. Присутствующие enum, amount/reason и retry delay проверяются по discriminator и диапазону; пустой safeMessage допустим, явный нулевой retry delay отклоняется. Manifest проверяется не только структурно: server-owned gateway несёт полный immutable D-43 binding, который совпадает с job до provider call, а каждый account/balance/transaction сопоставляется с объявленными product, log namespace, record kind и read action до сохранения evidence.

`integrations/domain` содержит provider-neutral значения; generated и provider DTO остаются в contract boundary. TypeScript boundary разделён на типы, общую валидацию, capabilities, wire codec и synthetic gateway; gateway хранит собственные неизменяемые снимки manifest/result. `integrations/application.Service` вызывает pre-read admission fence, сохраняет raw evidence с server-derived household/job и durable disposition `staged` до финансового commit и применяет страницу только через `admission.CommitPage`. Финансовый эффект, checkpoint/provider outcome и неизменяемая ingestion receipt из миграции 016 сохраняются одной транзакцией. При потере подтверждения commit отдельный bounded context читает receipt: подтверждённый результат финализирует disposition, а недоказанный оставляет evidence в `staged` без попытки угадать исход. Receipt сохраняется для `page`, `provider_outcome`, `rejected_result` и `stale_result`. После рестарта `ReconcileStaged` читает staged batches и terminal receipts по server-owned household/job/evidence reference. Найденный receipt завершает disposition без повторного применения; отсутствие receipt оставляет evidence staged. Только доказанный отказ до commit и успешное durable retention получают `rejected_result`. Disposition финализируется идемпотентно. Сервер назначает evidence/fetch/operation/source revision, principal и внутренние account IDs. Application разрешает account descriptor отдельно от observation; balance/posting используют descriptor той же самостоятельной страницы. Accounts-owned policy применяет подтверждённые Raiffeisen/Ozon `RUR → RUB`, сохраняя raw code; неизвестные symbols остаются unsupported. D-39 source key кодирует части структурно и не использует сумму, время, connection, cursor, locator, page-local evidence ID или локализованный текст. Payload hash строится из нормализованной записи без evidence ID и отдельно подтверждённого raw digest. Карточные alias отклоняют PAN/CVV, Unicode-цифры и любые цифры кроме собственных последних четырёх ASCII-цифр. Комиссия остаётся отдельной проводкой; свободный `feeId` отклоняется до появления типизированного correspondence-контракта.

Synthetic golden page покрывает RUB, USD, USDT, USDC, BTC, ETH и неподдерживаемый USDC.E; отдельная Raiffeisen fixture покрывает raw RUR с canonical RUB. Разные продукты/аккаунты, карточный alias, known/unknown, partial coverage, точные дроби, pending расход, net trade P&L с included fee/valuation и mining reward сохраняют смысл. Reconnect/replay не дублирует account, opening, observation, source revision или posting. Ошибка evidence storage не открывает финансовый commit; stale admission и delayed provider failure сохраняют evidence в quarantine без checkpoint/финансового эффекта. Отвергнутая после staging страница получает `rejected_result` с trusted ownership. Обнаруженная сервером account/source ambiguity предварительно группирует полные D-39 keys страницы, дедуплицирует одинаковые факты, сохраняет отдельные omissions, не проводит ни одну запись конфликтующей группы и не откатывает независимые записи страницы; объявленная ambiguous revision не может завершить checkpoint с complete coverage. Reauth/MFA/CAPTCHA переводят job в ожидание, rate-limit/temporary failure — в ограниченный повтор с сохранённой задержкой, необратимый отказ — в terminal failure. Evidence каждого provider outcome связывается с household/job в той же fenced-транзакции, что и смена состояния задания.

## Матрица проверок

Обязательные команды: `make check`; `make check-contracts`; `make test-collector FILTER=contracts`; `make test-integration AREA=all`; race suites ingestion/jobs/storage/accounts/ledger/audit/matching/reconciliation; `git diff --check`. PostgreSQL suite использует изолированную локальную PostgreSQL 17.11 под непривилегированной ролью и завершается ошибкой без `WANT_KEEP_TEST_DATABASE_URL`. Конкретные результаты кандидата и CI фиксируются в PR.

Тесты проверяют account-only page без выдуманного observation, точный gateway/job binding до provider IO, manifest/provider mismatch до evidence, immutable synthetic fixtures, provider failure lifecycle и durable evidence association без финансового apply, exact failure cursor, heartbeat после продвижения checkpoint и гонку delayed failure, повтор и конкурентную доставку, точность PostgreSQL NUMERIC, Raiffeisen RUR/RUB boundary, family/job-derived actor, структурные account/source identities, Unicode round trip, initial staged/final rejected-result disposition и quarantine stale result, strict null/required-field parity, receipt readback после неизвестного результата commit и same-page source collision. Отдельные регрессии покрывают server-derived account ambiguity, declared source ambiguity, совокупный gaps limit с транзакционным rollback, omitted/zero lookback, optional empty/absent canonical parity, retry delay и запрет `feeId`. Варианты PAN с точками, slash, zero-width и Unicode-цифрами отклоняются. Ingestion fixtures запрашивают удаление собственной синтетической БД после каждого теста; длинная локальная матрица может потребовать сброса disposable tmpfs из-за сохраняемого PostgreSQL WAL. Golden fixtures проверяют финансовый смысл, а не только JSON shape.
