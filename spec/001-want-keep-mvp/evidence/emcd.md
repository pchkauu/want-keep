## Текущий объём: D-34

Владелец явно включил используемые криптокарты, Coinhold/Grow, кошелёк USDT и ранее использовавшийся P2P. Майнинг не использовался ни сейчас, ни ранее; его данные и история не требуются. Майнинг, торговый терминал, стейкинг, Portfolio, Borrow, реферальные программы и другие неиспользуемые продукты/кошельки отложены. Их исследование **не блокирует EMCD/MVP**; расширение позже требует нового подтверждённого контракта. Общие функции Want Keep и другие провайдеры сохраняются.

Движения включённого кошелька не отбрасываются из-за отложенного связанного продукта. Их исходная сумма, статус и происхождение сохраняются; неизвестная семантика требует уточнения. Криптокарта не считается кредиткой без доказанного кредитного договора. EUR в карточной покупке — исходная валюта операции, а не новое требование открыть EUR-кошелёк или добавить EUR в переключатель оценки.

## Контракт адаптера и незакрытые поля

AS IS: действующая сессия → выбранный продукт → история → детали. Отдельные frontend-модули и версия Mining API не доказывают общий финансовый API. В этой итерации нет HAR или реального JSON request/response выбранных продуктов. Нельзя выдавать UI-маршрут за HTTP read endpoint или строить финансовый импорт парсингом подписей.

| Граница | Что обязан получить task-0.10 перед task-4.6 |
| --- | --- |
| Доступ | Подтверждённый бесплатный личный API либо допустимый структурированный способ чтения кабинета; scopes, auth, срок/обновление сессии, лимиты запросов и почасовой режим. Не переносить mining API permissions на остальные продукты |
| Identity | Проверенный внешний владелец, постоянные ID кошелька/вклада/карты и операций в namespace household/provider/external-account/product/log. UUID в UI — кандидат, не доказанная устойчивость после reauth. Маска, адрес, валюта, connectionId, текст и сумма не identity |
| Балансы | Native asset/amount/scale, sourceAsOf, отдельные owned/available/locked с известностью. Установить состав агрегатов, Grow principal/accrued/capitalized, карточного резерва и средств на выводе. Не включать весь Grow в расходный пул; не вычитать неизвестный hold как ноль |
| Wallet | Тип, направление, status, source ID/revision, время/зона, fee и gross/net, network/hash для сетевого перевода. TxID отсутствует у части внутренних движений; он не универсальный ID |
| Grow | Начальный капитал, движения, ставка с effective dates, day-count, rounding, cutoff, срок/режим выхода, капитализация/выплата и продление. Начисление отражается один раз; последующая капитализация или перевод уже признанного дохода не создаёт его повторно |
| Карта | Раздельные authorization/clearing/hold/release/decline/refund/reversal и fee; связь USDT → USD при пополнении. Покупка с отказом не расход по основной сумме; комиссия учитывается только по подтверждённому эффекту. Не складывать авторизацию с проведением |

| Семья и безопасность | Второй независимый аккаунт, повторное подключение одного источника, reauth владельцем, версия/lease и запрет применения старого результата после отключения. Не извлекать PAN/CVV, ключи, cookies и переписку для AI |

## Синтетические сценарии

[emcd.samples.json](emcd.samples.json) содержит шесть **проектных проверочных сценариев**, а не ответы EMCD. Все значения вымышлены; `source_request`/`source_response` равны null, потому что контракт не получен. Сценарии задают ожидаемые решения для будущих fixtures:

1. Родительская сводка и дочерние wallet/Grow не складываются дважды; карточный резерв отдельно от available, неизвестное available остаётся null.
2. Начисление вознаграждения, его капитализация и выплата дают один доход; изменение формы хранения не новый доход.
3. Отклонённая покупка имеет нулевой основной расход; отдельно подтверждённая комиссия сохраняется, неизвестная — ожидает доказательства.
4. Пополнение карты USDT → USD связывается как обмен/внутреннее движение; комиссия отдельно, паритет не предполагается.
5. P2P-ордер, движение кошелька и банковское поступление дают один обмен; округлённые числа UI не пересчитывают точные source amounts.
6. Последняя страница UI одного Grow не означает completeness всех журналов и не является подтверждённым API-терминатором.

## Проверка результата

Выполнены read-only UI-наблюдения и проверка официальных источников. Команды для финального состава: `make docs-check` (spec check и тесты генератора), проверка JSON/Decimal-сценариев, RU/EN IDs/ссылок/смысла и `git diff --check`. Результат запуска и доставка фиксируются в отчёте Issue #6 после проверки.

Не выполнены: HTTP replay/API-вызовы с credentials, полный импорт всех страниц, reauth/второй аккаунт, почасовой runtime, enforcement allowlist, прогнозы, tests/build/E2E приложения. Причины: контракт выбранных API не получен, финансовые сценарии и EMCD-адаптер отсутствуют; основа task-1.1 уже есть. Нет утверждения о прохождении AC-047/AC-041/AC-048/AC-070/AC-079/AC-087 в runtime. Старый Avida pass не относится к этому исследованию; текущий self review проверяет документацию.

Проверки итогового состава на базе `f12f215`: `make docs-check` — pass, 87 REQ / 105 AC / 67 задач / 35 экранов / 67 GitHub mappings; 14 тестов генератора — pass. Шесть Decimal-сценариев, соответствие 26 наблюдений/ID/ссылок RU/EN, JSON, ограничение diff каталогом EMCD и отсутствие приватных ID — pass. Проверен отдельный состав публикации; незавершённые изменения другого исследования сохранены.

## Решение task-0.10, 2026-09-07

EMCD-B02–B04 выше становятся entry/deployment gate task-4.6. D-34 ограничивает scope, D-39 разделяет aggregate/wallet/Grow/card/P2P namespaces и запрещает UI-derived postings. Авторизованная вкладка Chrome подтвердила доступ к выбранным разделам и history/pagination controls без публикации значений или opaque IDs; response bodies не экспортировались.

До deployment нужны permission, structured fixtures каждого журнала, stable identity, full pagination/coverage, revisions/statuses/fees, balance/Grow/card/P2P lifecycle, reauth и два аккаунта. Unknown/collision не проводят деньги. SDD Ready не заявляет работающий EMCD connector.
