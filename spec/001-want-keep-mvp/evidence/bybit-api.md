# Bybit: авторизованное чтение API

[English](bybit-api.en.md) · [Исследование и официальная матрица маршрутов](bybit.md) · [Синтетические сценарии](bybit.samples.json)

Дата: 2026-09-07. Владелец разрешил выпуск RSA-ключа и подписанное чтение из среды с разрешённым IP. Это дополнение к исследованию контрактов task-0.4, не работающий коннектор Want Keep. BYBIT-E01–E10 сохраняют первичные наблюдения UI/публичного API; новые доказательства уточняют прежние предположения о приватном доступе.

## Доступ и граница секретов

BYBIT-E11 — **confirmed**: `GET /v5/user/query-api` вернул `readOnly=1`, `isMaster=true`, непустой `userID`, заданное ограничение IP и ровно следующие непустые права: `Wallet: [AccountTransfer]`, `Exchange: [ExchangeHistory]`, `Earn: [Earn]`, `FiatP2P: [FiatP2POrder]`. Права торговли, вывода и объявлений не включены. Этот набор достаточен в проверке, но необходимость каждого отдельного разрешения не доказана. Название `AccountTransfer` не разрешает переводы: режим ключа и будущий allowlist маршрутов должны независимо ограничивать интеграцию чтением.

[Подпись RSA](https://bybit-exchange.github.io/docs/v5/guide) использует SHA256/PKCS#1 v1.5 и base64 для timestamp + API key + receive window + точной query string или POST JSON. Приватный ключ остаётся локально; Bybit получает публичный. Владелец ввёл MFA и сохранил выданный API-ключ. Файлы ключей имеют права 0600, каталог приватного ключа — 0700. API-ключ и локальные сырые ответы исследования исключены из Git. Ключ, IP, UID, подпись, сырой ответ, платёжные реквизиты и личное расположение секретов не включаются в публичные документы, Issues, AI-контекст или логи приложения. Ответ проверки ключа сам содержит `apiKey` и требует фильтрации. Локальные игнорируемые файлы — материалы исследования, не production-хранилище секретов или схема резервирования.

Аккаунт принял `https://api.bybit.com`. Платная подписка API не приобреталась. Выбранный VPS, последующее истечение/ротация/отзыв и ключ второго владельца не проверялись. Отказ API остаётся ошибкой доступа, не поводом расширять права или автоматически переключаться на браузер. Финансовых изменений нет; единственные POST для чтения — два явно разрешённых маршрута P2P.

## Передача контракта

Использовать официальный API для Funding, Flexible Easy Earn и P2P. Пробел API, требующий браузера, в необходимых маршрутах не обнаружен. Identity/версии источника отделяются от финансового события; совпадения сумм/времени — кандидаты с проверкой неоднозначности, не разрешение автоматического слияния. Финансовая классификация не строится только на Funding localization keys. Неизвестные статусы/единицы дают видимую неразрешённую запись.

BYBIT-B01/B02/B05 закрыты для проверенного доступа. D-39 закрывает SDD-часть BYBIT-B03/B04: route-specific identity, candidate-only linkage, hourly collision и history-gap behavior. task-4.4 владеет executable conformance, error/revocation, вторым аккаунтом и end-to-end приёмкой. Неиспользуемые продукты не блокируют; финансовый runtime не заявлен.

Проверены официальные read-ответы, исходные типы/единицы, пагинация всех запросов, точная Decimal-арифметика и replay. Документация проверяется `make docs-check`, синтетической арифметикой и RU/EN/diff/privacy review. Не выполнялись production-тесты адаптера, сопоставление с банком, все смены статусов, второй владелец/отзыв, VPS и E2E приложения. Исследование эти проверки не заменяет.

## Решение task-0.10, 2026-09-07

D-39 разрешает выявленные BYBIT-B03/B04 без ложного объединения: route namespaces, candidate-only links, hourly tuple fallback с collision detection и `source_partial` для history/lifetime gaps. task-4.4 превращает это evidence в executable fixtures и отдельно доказывает второй аккаунт, rotation/revocation и provider deployment gate.
