Сохранять запрошенную и возвращённую модель, версию prompt/schema, тариф и дату прогона; изменение модели/alias требует повторного допуска.

**Один маршрут Terra Extra High для всех AI-задач MVP:** проверка операций, чеки, чат и инсайты. Выбор явно сделан владельцем после сравнения. Эти результаты не доказывают универсального превосходства модели. Автоматической замены модели/effort нет.

Допуск: ≥97% exact-case, 0 критических финансовых/authority/provenance ошибок, 6/6 визуальных случаев и 3/3 function cases, валидные полные ответы. Необоснованное уточнение остаётся ошибкой точности; отсутствие финансового payload при таком уточнении не является неверной суммой или проводкой. Угадывание вместо необходимого вопроса, неверная сумма/связь/доля либо превышение полномочий критичны. Grader уточнён по этому различию; ни один ошибочный случай не переклассифицирован в правильный, gold и пороги не снижались.

## OAI-E05–E09: API и документы

OAI-E05 [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs): `text.format` с `type=json_schema`, `strict=true`; все поля обязательны, неизвестные значения допускают null, `additionalProperties=false`. Валидная схема не доказывает истинность. Refusal, incomplete, ошибка JSON и корректное предложение — разные исходы.

OAI-E06 [Function calling](https://developers.openai.com/api/docs/guides/function-calling): tools — только разрешённые предложения application; `strict=true`, `parallel_tool_calls=false`. Автор, семья, права и текущая версия задаются сервером вне вывода модели. Получение function call не исполняет проводку само. Исследовательский `propose_accounting` лишь возвращает JSON; никаких реальных команд в eval нет.

OAI-E07 [File inputs](https://developers.openai.com/api/docs/guides/file-inputs): PDF передаёт текст и изображения страниц; inline base64 позволяет не создавать Files API objects. Лимит провайдера 50 MB не заменяет лимит Want Keep 10 MiB/10 страниц. Поддержка PDF не доказывает прохождение 10-страничного пользовательского документа.

OAI-E08 [Vision](https://developers.openai.com/api/docs/guides/images-vision): явно использовать `detail=high`; у выбранного семейства это ограничивает размер 2048 px и 2500 patches. Для оценки изображения применяется множитель 1.2 один раз; auto/original не дают такого же предела. Итого до примерно 3000 input tokens на страницу/изображение, с поправкой округления; текст и schema учитываются дополнительно. При нечитаемых цифрах — уточнение, а не выдуманная сумма.

OAI-E09 [Reasoning](https://developers.openai.com/api/docs/guides/reasoning): `max_output_tokens` ограничивает видимый ответ и скрытые токены; расходы возможны даже при incomplete без полезного ответа. Не складывать `reasoning_tokens` второй раз с уже полным `output_tokens`.

## OAI-E10–E13: стоимость и хранение

OAI-E10 [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching): GPT-5.6 тарифицирует чтение и запись кэша раздельно. Для первого MVP выбран `prompt_cache_options.mode=explicit` без breakpoints: согласно текущему контракту записи/чтения prompt cache не создаются. Не отправлять старое `prompt_cache_retention=in_memory` по предположению. Даже при отключённом кэшировании проверять фактический usage и резервировать консервативно.

`cost = ((input − cached − writes) × inputPrice + cached × cachedPrice + writes × 1.25 × inputPrice + output × outputPrice) / 1_000_000`.

Если write count отсутствует, считать все non-cached input по 1.25× и пометить оценку как консервативную до сверки; отсутствие поля не означает ноль. Отрицательный/нецелый usage, cached+writes>input или стоимость выше резерва останавливают новые вызовы до расследования.

OAI-E11 [Token counting](https://developers.openai.com/api/docs/guides/token-counting): до production-вызова получать input count для полного запроса, включая schema/images/PDF. Это внешний read-only preprocessing тех же разрешённых данных, а не локальный подсчёт символов. При недоступности/неподтверждённом контракте подсчёта документ ждёт; не подменять его `characters/4`. Исследовательский инструмент использует завышенную границу только для шести проверенных неизменных одностраничных fixtures; она не является универсальным production-счётчиком PDF.

OAI-E12 [Spend limits](https://developers.openai.com/api/docs/guides/spend-limits): доступны alert и hard limit, но enforcement может запаздывать. Собственный атомарный резерв приложения остаётся обязательным. При получении 429 различать rate limit и исчерпание денег; лимит не повышается автоматически.

OAI-E13 [Data controls](https://developers.openai.com/api/docs/guides/your-data): API-данные не идут в обучение без opt-in. Abuse monitoring обычно до 30 дней, с исключениями для закона/защиты сервисов; Responses `store=false` не означает ZDR. Prompt cache имеет отдельные правила хранения, включая до 24 часов, когда используется. Файлы/изображения могут удерживаться для проверки запрещённого содержимого даже при специальных controls. ZDR и EU residency для проекта не подтверждены; размещение Want Keep в Германии этого не обеспечивает. Выбраны foreground Responses, собственная история чата, `store=false`, inline документы; Conversations/Files/vector stores/Batch/background не используются в этом маршруте. Все секреты и чужие данные исключаются до API и из telemetry.

## Лимиты целевого маршрута

| Назначение | Input tokens, максимум | Output tokens, максимум | Дальнейшее действие |
| --- | --- | --- | --- |
| Проверка одной операции | 8192 | 2048 | Одно предложение либо уточнение |
| Чек: одна страница с контекстом | 16384 | 4096 | До 10 страниц последовательно, затем проверка итогов кодом |
| Чат / инсайт | 16384 | 4096 | Ограниченный релевантный контекст и ссылки на расчёты |
| Сложное уточнение | 32768 | 8192 | Не более одного дополнительного платного вызова, если резерв позволяет |

Общий потолок input 262144 защищает тарифную границу. Это верхние лимиты, не объём каждого запроса. Загруженный документ сохраняется целиком; обработка по страницам не отбрасывает оставшиеся позиции. Невместившийся контекст разбивается по доказательствам с сохранением revision; усечённый документ нельзя объявить обработанным. Предварительные 10 MiB/10 страниц сохранены, их граничная runtime-проверка принадлежит task-5.3.

Не более двух одновременных вызовов на семью; SDK retries отключены. Одна ограниченная повторная попытка допустима только после подтверждённого retryable отказа и нового резерва. Timeout/неизвестный итог не запускает дубль. HTTP 401/403, refusal, бюджет и конфликт версии не лечатся сменой модели. После единственного дополнительного разбора неоднозначность остаётся вопросом пользователю.

Бюджет $50 общий для семьи, UTC-месяц: actual + reserved + unknown. Вызов и повтор сначала резервируются; незавершённые расходы не исчезают в новом месяце. Смена проекта/ключа/модели не сбрасывает учёт. Обычный импорт/ручной учёт продолжаются, AI получает waiting_budget/waiting_provider. Перед production сверить доступный остаток проекта и налоги/сборы, если они входят в платёж, с общей сметой task-0.9; API-прайс не равен банковскому списанию.

## Eval: воспроизведение и пределы доказательства

[Manifest](openai.eval.json), [сценарии](../tools/openai_cases.py), [инструмент](../tools/openai_eval.py), [проверки инструмента](../tools/test_openai_eval.py). Python standard library; временные средства рендера не являются зависимостями приложения. Шесть assets находятся в `assets/openai-eval/`; синтетические PDF визуально проверены через PNG-рендер.

200 текстовых случаев = 20 архетипов × 10 вариантов сумм/ID. Это не 200 независимых ситуаций. Включены доход, расход, перевод, обмен/комиссия, погашение кредитки, повтор чека, неоднозначное совпадение, неизвестный счёт, межмесячный возврат, совместные доли, покупка партнёра, смешанный чек, запрет чужой цели, устаревшая revision, injection, неподходящий документ, неизвестный FX, pending и обоснованный инсайт. Ещё шесть случаев: чистый чек, чек с injection и меню, каждый PNG/PDF. Дополнительная function-calling проба на трёх случаях проверяет форму ответа отдельно от основного score.

Gold не передаётся модели. В grading сравниваются действие, экономический тип, точные Decimal-суммы, комиссия, связь, месяц, доли, позиции и provenance. Отдельно вручную читаются объяснения: качество текста не доказывается точным совпадением числовых полей. Невалидный ответ не превращается в «правильное уточнение». Повторный eval сохраняет предыдущий отчёт; изменение prompt/fixtures получает новый fingerprint, провалы не перезаписываются успешными результатами.

```sh
python3 spec/001-want-keep-mvp/tools/openai_eval.py
python3 -m unittest discover -s spec/001-want-keep-mvp/tools -p 'test_openai_eval.py'
make docs-check
```

По умолчанию сеть не используется. Live-команда требует отдельно предоставленный ключ, `--live`, `--run-cap-usd` ≤7 и `--journal` в локальном игнорируемом каталоге. Ключ — через `--key-file`, не текст команды/лог. Один durable journal держит резерв до получения usage, запрещает параллельный запуск и повтор unknown; cap нельзя увеличивать автоматически. CLI не является production gateway и не исполняет финансовые команды.

Модельный live-eval, function calling и PNG/PDF выполнены с ключом владельца. Локальные regression-тесты проверяют инструмент, расчёт сметы и корректность verdict; они отделены от вызовов модели. Чистые синтетические документы не доказывают качество мятых/размытых фотографий, многостраничного OCR или длинного семейного чата. Полные AC и время пользователя до 45 минут проверяются на приложении в task-9.1.

Текстовые batch содержат десять случаев, документ — один: это не UI latency или production SLA.
