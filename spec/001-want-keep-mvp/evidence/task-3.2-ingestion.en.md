## Proven result

`collector/contracts/v10/ingestion.openapi.yaml` is the single wire-model source. `make generate-contracts` creates Go transport DTOs in `backend/internal/integrations/contract/generated` and TypeScript types in `collector/src/contracts/generated`; `make check-contracts` reproduces both outputs in a temporary directory. Strict Go/TypeScript codecs consistently reject missing required fields, explicit `null`, unknown fields and trailing JSON. They also enforce aligned Unicode code-point and separate byte limits, reject NUL/lone surrogates and invalid base64/digests, and require valid dates, canonical UTC instants with `Z`, decimal strings, consistent discriminators and exact server-issued job/binding/admission-revision/cursor echoes for pages and provider failures. The cursor is checked only when a sync result commits; immutable lease identity keeps heartbeat valid after checkpoint advancement. Omitted lookback remains `nil` while explicit zero is rejected; cumulative coverage after merging the checkpoint accepts at most 100 unique gaps of 2,000 code points, and overflow rolls the page back without advancing the cursor. Optional empty merchant, note, network and aliases values canonicalize as absent. Present enums, amount/reason and retry delays are checked against their discriminator and range; an empty safeMessage is valid while an explicit zero retry delay is rejected. The manifest is more than a structural declaration: the server-owned gateway carries the full immutable D-43 binding and matches it with the job before a provider call, while every account, balance and transaction is checked against its product, log namespace, record kind and required read action before evidence storage.

`integrations/domain` contains provider-neutral values; generated and provider DTOs remain at the contract boundary. The TypeScript boundary is split into types, common validation, capabilities, wire codec and synthetic gateway; the gateway owns immutable manifest/result snapshots. `integrations/application.Service` runs the pre-read admission fence, persists raw evidence with server-derived household/job ownership and a durable `staged` disposition before the financial commit and applies a page only through `admission.CommitPage`. The financial effect, checkpoint/provider outcome and immutable ingestion receipt from migration 016 commit together. When commit acknowledgement is lost, a separate bounded context reads the receipt: a proven result finalizes the disposition, while an unproven result leaves evidence `staged` instead of guessing. Only a proven pre-commit rejection with successful durable retention receives `rejected_result`. Disposition finalization remains idempotent. The server assigns evidence/fetch/operation/source revision, principal and internal account IDs. The application resolves an account descriptor independently from an observation; balances/postings use a descriptor from the same self-contained page. An accounts-owned policy applies confirmed Raiffeisen/Ozon `RUR → RUB` mappings while preserving the raw code; unknown symbols stay unsupported. A D-39 source key structurally encodes its parts and excludes amount, time, connection, cursor, locator, page-local evidence ID and localized text. The payload hash uses the normalized record without evidence ID plus the separately verified raw digest. Card aliases reject PAN/CVV, Unicode digits and any digits except their own last four ASCII digits. A fee remains a separate posting; free-form `feeId` is rejected until typed correspondence exists.

The synthetic golden page covers RUB, USD, USDT, USDC, BTC, ETH and unsupported USDC.E; a separate Raiffeisen fixture covers raw RUR with canonical RUB. Distinct products/accounts, a card alias, known/unknown, partial coverage, exact fractions, a pending expense, net trade P&L with an included fee/valuation and a mining reward retain their meaning. Reconnect/replay duplicates no account, opening, observation, source revision or posting. Evidence-storage failure never opens a financial commit; stale admission and a delayed provider failure retain evidence in quarantine without a checkpoint or financial effect. A page rejected after staging receives a `rejected_result` with trusted ownership. Server-detected account/source ambiguity preflights complete D-39 keys across the page, deduplicates identical facts, retains separate omissions, posts none of a conflicting group and does not roll back independent page records; a declared ambiguous revision cannot complete a checkpoint with complete coverage. Reauthentication/MFA/CAPTCHA move the job to waiting, rate-limit/temporary failures use bounded retries with the declared delay, and irreversible errors become terminal failures. Every provider outcome's evidence is associated with its household/job in the same fenced transaction as the job-state transition.

## Verification matrix

Required commands are `make check`; `make check-contracts`; `make test-collector FILTER=contracts`; `make test-integration AREA=all`; ingestion/jobs/storage/accounts/ledger/audit/matching/reconciliation race suites; and `git diff --check`. The PostgreSQL suite uses isolated local PostgreSQL 17.11 under the unprivileged role and fails without `WANT_KEEP_TEST_DATABASE_URL`. Exact candidate and CI outcomes are recorded in the PR.

Tests cover an account-only page without an invented observation, exact gateway/job binding before provider IO, manifest/provider mismatch before evidence, immutable synthetic fixtures, provider-failure lifecycle and durable evidence association without financial apply, exact failure cursor, heartbeat after checkpoint advancement and a delayed-failure race, replay and concurrent delivery, exact PostgreSQL NUMERIC, the Raiffeisen RUR/RUB boundary, family/job-derived actor, structural account/source identities, Unicode round trips, initial staged/final rejected-result disposition, stale-result quarantine, strict null/required-field parity, receipt readback after an unknown commit outcome and same-page source collision. Focused regressions cover server-derived account ambiguity, declared source ambiguity, the cumulative gap cap with transactional rollback, omitted/zero lookback, optional empty/absent canonical parity, retry delay and rejection of `feeId`. PAN variants using dots, slashes, zero-width separators or Unicode digits are rejected. Ingestion fixtures request deletion of their synthetic database after every test; a long local matrix may still require resetting the disposable tmpfs because PostgreSQL retains WAL. Golden fixtures assert financial meaning instead of JSON shape alone.
