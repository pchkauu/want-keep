## Proven result

`collector/contracts/v10/ingestion.openapi.yaml` is the single wire-model source. `make generate-contracts` creates Go transport DTOs in `backend/internal/integrations/contract/generated` and TypeScript types in `collector/src/contracts/generated`; `make check-contracts` reproduces both outputs in a temporary directory. Strict Go/TypeScript codecs enforce aligned Unicode code-point and separate byte limits, reject NUL/lone surrogates, unknown fields, trailing JSON and invalid base64/digests, and require valid dates, canonical UTC instants with `Z`, decimal strings, consistent discriminators and exact server-issued job/binding/admission-revision/cursor echoes. Omitted lookback remains `nil` while explicit zero is rejected; coverage accepts at most 100 unique gaps of 2,000 code points. The manifest is more than a structural declaration: the server-owned gateway carries the full immutable D-43 binding and matches it with the job before a provider call, while every account, balance and transaction is checked against its product, log namespace, record kind and required read action before evidence storage.

`integrations/domain` contains provider-neutral values; generated and provider DTOs remain at the contract boundary. The TypeScript boundary is split into types, common validation, capabilities, wire codec and synthetic gateway; the gateway owns immutable manifest/result snapshots. `integrations/application.Service` runs the pre-read admission fence, persists raw evidence before the financial commit and applies a page only through `admission.CommitPage`. The server assigns evidence/fetch/operation/source revision, principal and internal account IDs. The application resolves an account descriptor independently from an observation; balances/postings use a descriptor from the same self-contained page. A D-39 source key structurally encodes its parts and excludes amount, time, connection, cursor and localized text. Card aliases reject PAN/CVV, Unicode digits and any digits except their own last four ASCII digits. A fee remains a separate posting; free-form `feeId` is rejected until typed correspondence exists.

The synthetic golden page covers RUB, USD, USDT, USDC, BTC, ETH and unsupported USDC.E; distinct products/accounts, a card alias, known/unknown, partial coverage, exact fractions, a pending expense, net trade P&L with an included fee/valuation and a mining reward. Reconnect/replay duplicates no account, opening, observation, source revision or posting. Evidence-storage failure never opens a financial commit; stale admission retains evidence in quarantine without a checkpoint or financial effect. Server-detected account/source ambiguity retains separate omissions, posts no dependent operation and does not roll back independent page records; a declared ambiguous revision cannot complete a checkpoint with complete coverage. Reauthentication/MFA/CAPTCHA move the job to waiting, rate-limit/temporary failures use bounded retries with the declared delay, and irreversible errors become terminal failures. Every provider outcome's evidence is associated with its household/job in the same fenced transaction as the job-state transition.

## Verification matrix

Required commands are `make check`; `make check-contracts`; `make test-collector FILTER=contracts`; `make test-integration AREA=all`; ingestion/jobs/storage/accounts/ledger/audit/matching/reconciliation race suites; and `git diff --check`. The PostgreSQL suite uses isolated local PostgreSQL 17.11 under the unprivileged role and fails without `WANT_KEEP_TEST_DATABASE_URL`. Exact candidate and CI outcomes are recorded in the PR.

Tests cover an account-only page without an invented observation, exact gateway/job binding before provider IO, manifest/provider mismatch before evidence, immutable synthetic fixtures, provider-failure lifecycle and durable evidence association without financial apply, replay and concurrent delivery, exact PostgreSQL NUMERIC, family/job-derived actor, structural account/source identities, Unicode round trips and stale-result quarantine. Focused regressions cover server-derived account ambiguity, declared source ambiguity, gap limits/uniqueness, omitted/zero lookback and rejection of `feeId`. PAN variants using dots, slashes, zero-width separators or Unicode digits are rejected. Ingestion fixtures request deletion of their synthetic database after every test; a long local matrix may still require resetting the disposable tmpfs because PostgreSQL retains WAL. Golden fixtures assert financial meaning instead of JSON shape alone.
