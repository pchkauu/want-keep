# Task-2.1 — счета и начальные остатки

Реализованы наличные счета, versioned corrections открытия, смена принадлежности, admitted импорт продуктов/алиасов/снимков, точные проекции и HTTP API счетов/восстановления команд. База: `ce25bf1515f8564e6493676fca060451d324986a`; ветка: `feat/task-2.1-accounts-opening-balances`. Зависимости task-1.3/1.4/1.5/1.6 включены в базу. [Контракт](../contracts.md#task-21--счета-и-начальные-остатки) фиксирует финансовые границы и права. Новых зависимостей, production deployment и изменений применённых миграций нет.

Миграция 007 сохраняет точные NUMERIC, наносекунды, независимые известность/покрытие/свежесть, составные семейные FK и неизменяемые записи открытия/источника/аудита под ролью приложения. Снимки отделены от журнала. Создание и corrections используют отдельную pending-регистрацию, затем атомарные журнал/проекцию/аудит/outbox/результат с повторной проверкой сессии и членства. Импорт работает в CommitPage после проверки admission, поколения connection и lease; неоднозначность/неподдерживаемый символ сохраняют evidence в quarantine без финансового эффекта. Для источника и наличных действует единая политика доступности, общая с резервами.

## Матрица проверок

Обязательные локальные команды: `make check`, `make test-integration AREA=accounts`, `make test-accounts-race`, integration/race для storage/identity/household, `make test-integration AREA=privacy`, `git diff --check`. Изолированная PostgreSQL 17.11 закреплена digest. Отсутствие БД завершает accounts integration ошибкой. CI сохраняет проверки базы и добавляет accounts integration/race. Точные локальные и CI-результаты привязываются к опубликованному кандидату в PR/отчёте; реальные продуктовые, браузерные и provider-проверки учитываются отдельно.

Новые accounts-тесты проверяют семь счетов/шесть активов через HTTP → Go → PostgreSQL → JSON, дробные USDC/BTC/ETH, открытие 5000 минус расход 500, corrections и перенос даты с сохранением истории, действующие/отменённые эффекты и границы дня с наносекундами. Покрыты replay/другой payload, конкурентные revisions, rollback, восстановление потерянного ответа по прежнему ключу, личное чтение recent/expired исходов, session/CSRF, две семьи в одной БД и correction открытия партнёром. Импортные тесты проверяют reconnect, разные продукты/внешних владельцев, алиасы, раздельный долг/лимит, старые/повторные/противоречивые наблюдения, partial-историю, неподдерживаемые символы, quarantine, устаревший admission и разделение источника/журнала. Домен проверяет unknown/stale/partial доступность и суммы по активам без паритета. Session fixtures используют сохранённые синтетические credentials; реальный WebAuthn-верификатор проверяется существующей identity suite.
