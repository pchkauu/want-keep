# Aifory Pro: исследование контракта чтения

[English](aifory.en.md)

Дата: 2026-09-07, Europe/Moscow. Задача: [task-0.5 / Issue #5](https://github.com/pchkauu/want-keep/issues/5). База репозитория: `7189149`, ветка `docs/want-keep-mvp-sdd`. Среда: предоставленный владельцем авторизованный кабинет в Google Chrome. Версия приложения и серверных API не установлена.

**Исследование завершено с блокирующими выводами по автоматизации.** Выполнено чтение интерфейса RUB-счетов, USDT, ETH и используемой виртуальной карты. Структурированный контракт поставщика и автоматический импорт не проверены. BLK-05 остаётся открыт под контролем task-0.10; task-4.5 и MVP остаются **Not Ready**. Исследование может завершиться с такими выводами по правилу [README](../README.md).

## Текущий объём: D-33

Явное решение владельца от 2026-09-07: нужны RUB-счета, USDT, ETH и существующая криптокарта. Остальные продукты Aifory не используются в текущем объёме исследования и **не блокируют MVP**. Это изменение требований, а не утверждение, что платформа не имеет других продуктов.

| Включено | Граница |
| --- | --- |
| RUB | Отдельные счета и их группы; остатки и движения, включая обмены, внесение/выдачу наличных и комиссии |
| USDT | Кошелёк, наблюдаемая сеть TRC-20, остаток и все движения выбранного кошелька |
| ETH | Кошелёк Ethereum, точные суммы, выводы, обмены и комиссии; ETH добавлен в перечень активов Want Keep |
| Существующая виртуальная карта | Фактический баланс в USD, пополнения, оплаты, комиссии и статусы; не считать криптокарту кредитной картой |
| Будущее расширение | Другие валютные кошельки, другие виды карт, P2P как самостоятельный продукт, реферальный продукт и каталоги сервисов. Нет требования исследовать/подключать их сейчас |

Отложенный продукт не означает пропуск его движения по включённому кошельку. Если в истории есть оплата сервиса, перевод из реферального счёта или операция с сертификатом, сохраняются предоставленные источником сумма, статус, комиссия и происхождение. Неизвестная семантика требует уточнения, а не выдуманного дохода. Номера действующих сертификатов не собирать: они могут давать право на получение средств.

## AS IS и целевой адаптер

AS IS: действующая сессия → главный экран → выбранная группа/счёт или карта → список → модальные детали. Платформа владеет остатками и статусами; карточный процессинг — внешняя граница. Want Keep пока не получает ни одного автоматического результата импорта.

Ни одного подтверждённого HTTP request/response для Aifory в этом исследовании нет. `/home` и `/home/wallet` — маршруты UI, не API endpoints. Нельзя публиковать вымышленный curl, импортировать cookies в скрипт или выдавать JSON ниже за ответ поставщика.

Целевые правила для task-0.10/task-4.5, **ещё не реализованы**:

| Граница | Требование к подтверждаемому контракту |
| --- | --- |
| Доступ | Согласие оператора/допустимый способ чтения, бесплатность, auth/scopes, политика сессии, лимиты. Использовать официальный личный API, если он подтверждён; иначе разрешённый структурированный read-контракт кабинета |
| Account identity | Namespace household/provider/external-account/product/asset/network и постоянный ID продукта. connectionId — provenance; названия, адреса и маршрут не identity. Группы RUB не дублируют дочерние остатки |
| Money/балансы | Точные строки и provider scale; ETH не округлять до фиатных сотых. Сохранять исходные валюты USD/USDT отдельно. Непредоставленные available/locked/debt/asOf остаются неизвестными; RUB-платформенный кошелёк не маркировать банковским вкладом |
| Operations | Полные ID и revisions для каждого семейства операций, связанные source legs, native amounts, fees, status mapping, time с годом/зоной, источник доказательства. Не строить проводки из знака заголовка или OCR-текста |
| Card lifecycle | Доказанная связь authorization/clearing, отдельные fee/refund/reversal, hold/release. Похожая пара E12 должна уточняться до установления связи; нельзя списать дважды, слить разные покупки или вычесть hold повторно |
| Card funding | Связь USDT-списания и USD-зачисления, gross/net, валюта/база комиссии, курс и округление; это внутреннее движение с отдельной fee, не потребительский расход |
| История | Начало покрытия, год/зона, ordering, cursor/offset, пределы и признак конца. Сохранение подтверждённых страниц перед продвижением, перекрывающий повтор и reconciliation; неизвестная полнота не успешный полный импорт |
| Семейный доступ | Разные внешние аккаунты не объединяются; повторная авторизация связывается с тем же источником. Владелец выполняет MFA; disconnect/version fence исключает старый результат |
| Чтение | Exact origin/method/path/body allowlist; запрет открытия/пополнения/закрытия продуктов, повторения платежа, обмена, вывода и изменения безопасности. Наличие кнопки не разрешение сборщику |

Расширение поддерживаемых продуктов позже требует изменения D-33/REQ-046/AC-046, матрицы capability, evidence и соответствующих fixtures. Не требуется заранее реализовывать универсальный адаптер всех сервисов.

## Синтетические проверочные примеры

Это **проектные сценарии**, построенные по классам наблюдений, с полностью вымышленными значениями. Не provider fixtures, не реальные идентификаторы и не доказательство API.

```json
{
  "kind": "synthetic_mapping_cases",
  "eth_withdrawal": {
    "asset": "ETH",
    "received_before": "0.05000000",
    "recipient_amount": "0.04000000",
    "fee": "0.00300000",
    "history_debit": "0.04300000",
    "remaining": "0.00700000"
  },
  "card_funding": {
    "wallet_asset": "USDT",
    "card_asset": "USD",
    "wallet_header_sign": "+",
    "debit_wallet_ref": "wallet-example",
    "credit_card_ref": "card-example",
    "gross_debit": null,
    "fee": null,
    "executed_rate": null,
    "link_state": "needs_evidence"
  },
  "similar_card_rows": [
    {"amount": "-12.00", "asset": "USD", "source_status": "В процессе", "source_id": null},
    {"amount": "-12.00", "asset": "USD", "source_status": "Подтверждено", "source_id": null}
  ]
}
```

Ожидания: `0.04000000 + 0.00300000 = 0.04300000`, остаток `0.00700000`; комиссия не вычитается повторно. Неизвестные поля карточного пополнения остаются null. Пара похожих строк не становится доказанным расходом USD 24 или автоматически единым расходом USD 12: требуются ID/связь/статусы и затем одна подтверждённая проводка.

## Проверка результата

Выполнены: read-only UI-наблюдения E02–E17 в Chrome, просмотр официальных источников E18–E19, сравнение видимых native-сумм ETH, разбор неоднозначности карточных строк. SDD-проверка прошла: 87 REQ, 105 AC, 67 задач, 35 экранов и 67 GitHub mappings. 13 тестов генератора прошли. Проверены RU/EN-паритет идентификаторов/источников/JSON, точная арифметика Decimal, diff и отсутствие приватных данных в публикуемых примерах. Проверка отдельно выполнена на изолированном составе будущего коммита; незавершённые изменения другого провайдера в него не включены.

Команды: `python3 spec/001-want-keep-mvp/tools/spec_tool.py check`, `python3 -m unittest discover -s spec/001-want-keep-mvp/tools -p 'test_*.py'`, `git diff --check`. Это проверки документации и генератора, не приложения.

Не выполнены: API/collector runtime, сбор HAR, полная выгрузка истории, cold start из DE/NL/BG, hourly sync, reauth/MFA/expiry, второй аккаунт, replay/429/5xx, refund/reversal и денежная сверка всей карты. Причина: нет разрешённого подтверждённого структурированного контракта и необходимых runtime-образцов. Полные AC-046, AC-041, AC-048, AC-079, AC-087 не объявлены пройденными. Кредитные/накопительные условия Aifory не исследуются и не являются блокером текущего scope.
