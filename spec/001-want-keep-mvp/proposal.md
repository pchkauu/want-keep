# Want Keep MVP — описание продукта и решения

Execution mode: autonomous

Первичное согласование: 2026-09-06; семейное уточнение: 2026-09-07. Основание: подробное интервью и явный запрос пользователя реализовать согласованный план документации и GitHub backlog.

## Проблема и результат

Ручное ведение разрозненных фиатных и криптовалютных финансов занимает много времени. Want Keep собирает собственные счета, операции и документы в единый проверяемый учёт, помогает планировать месяц и объясняет результат через AI.

Первый выпуск — семейный пилот для пары. Ориентир нагрузки: сотни операций в месяц; ежедневная работа через чат, чеки, бюджет и уточнения — до 45 минут по оценке владельца. Текущего приложения для миграции нет; обязательный перенос старого Excel не входит в согласованный объём.

Результат текущего этапа: двуязычная спецификация, критерии, архитектура, матрица интеграций, полный backlog и самодостаточные GitHub Issues. Реализация приложения, приобретение инфраструктуры, commit/push и deployment этим этапом не выполняются.

## Сохранённые границы

Приложение читает платформы и изменяет только собственный учёт. Платежи, реальные переводы, торговые приказы и обход MFA/CAPTCHA не входят в продукт. Публичная регистрация, выход/замена участника семьи, дополнительные роли, мобильные экраны/адаптация, установка на домашний экран, native mobile, налоговая отчётность, управление майнингом и перенос старого Excel не входят в этот MVP.

Ручной ввод наличных и чеков обязателен. Ручная загрузка банковской выписки может помочь исследованию, но не закрывает требование автоматического подключения обязательного сервиса.

## Инженерные допущения

Это значения по умолчанию, а не ответы пользователя: базовый часовой пояс `Europe/Moscow` на первом запуске с явным выбором владельца; онлайн-работа с понятным offline-состоянием; две ступени категорий; private push без денежных деталей; money-weighted annualized XIRR для сравнения вложений; исходники хранятся для аудита. Формулы, ограничения файлов и ошибки описаны в [contracts.md](contracts.md).

Смена фундаментального контракта требует изменения обеих языковых версий, AC и зависимых задач. Технические версии библиотек, подтверждённые API, полные условия продуктов и тариф сервера ещё не выбраны — это результаты task-0.1–task-0.10, а не скрытые решения будущего исполнителя.

Документация и backlog могут быть доставлены до live-доступа. Ready полного MVP требует доказательства всех обязательных функций и продуктов. [verification.md](verification.md) сохраняет Not Ready до закрытия внешних контрактов; [backlog.md](backlog.md) содержит весь объём, включая заблокированные задачи.
